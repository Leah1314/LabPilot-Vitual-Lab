# Slack post — #hacksprint-sf-july

**We built LabPilot — an AI research assistant that refuses to lie about your data.** Point it at real antimicrobial-resistance data from BV-BRC for the gut-derived pathogens behind infected pancreatic necrosis, and it embeds 34,466 proteins with ESM2 on a **Daytona H100 in 93 seconds** — 74x faster than the two hours the same job took on our CPU. Then it does what no other AI dashboard does: it tells you when there's nothing there. We checked whether our own clusters actually separate resistant from susceptible isolates, found they don't, and shipped that verdict as a hard runtime gate instead of a pretty chart — so the **CopilotKit + Fireworks** agent is structurally incapable of claiming a resistance link the arithmetic doesn't support. Ask it "which cluster is most resistant?" and it refuses, and explains why. Swap in a dataset that genuinely has signal and the same agent finds it instantly. Grounding you can falsify in 30 seconds, not a promise in a system prompt. 🧬

**One gotcha worth passing on to anyone else running GPU sandboxes:** ours couldn't reach `dl.fbaipublicfiles.com` — the ESM2 weight download died partway with `[Errno 104] Connection reset by peer`, every time. Fix: fetch the weights locally and push them onto a **Volume**, which survives sandbox deletion and makes every later run a cache hit. Two neighbours of the same problem also cost us time — GPU sandboxes are *required* to be ephemeral (`auto_delete_interval=0`, hard-rejected otherwise), and `auto_stop_interval` defaults to 15 minutes and **fires mid-job**, so a long embedding run dies silently at minute 15 unless you set it to 0.
